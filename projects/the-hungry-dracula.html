01 / THE BRIEF

Can Dracula survive the snack run?

I built The Hungry Dracula as my first CS50 Week 0 project, using Scratch to turn the fundamentals of programming into a small, playable arcade game. The idea was simple: guide Dracula across the screen, catch the useful drops and dodge the things that can end the run.

The project combines custom pixel-art sprites and backdrops with a title screen, instructions, timed gameplay, scoring and a restart sequence. It gave me a practical way to work with events, variables, conditionals, loops and reusable procedures while building something with its own visual identity.

03 / THE BUILD

More than a sprite and a score.

The game is organised around broadcast messages that coordinate the different parts of the experience. This keeps the title screen, instructions, active game and game-over state working as distinct stages rather than one continuous script.

  1. Screen states and broadcasts

    A title screen leads into instructions and then the game arena. The start game broadcast synchronises player movement, falling items, audio and the countdown. When time expires, game over triggers the end screen and restart flow.

  2. Reusable item spawning

    I created a custom block, reset drop (delay), with a delay parameter. It resets each falling item to a position along the top of the arena, waits for the specified interval and reveals it during active play.

  3. Scoring and collision logic

    The score and timer variables track the round. Conditional checks detect collisions with Dracula, handle points and penalties, and return items to the top when they leave the arena.

  4. Loops and timing

    repeat until loops keep the countdown, character movement, item drops and background audio running in sync until the 30-second round ends.

05 / WHAT I LEARNED

Learning by making.

EVENT-DRIVEN THINKING

Using broadcasts to coordinate separate sprites and game states made the project easier to organise and reason about.

REUSABLE LOGIC

The parameterised drop procedure showed how a custom block can reduce repetition while allowing different timing behaviour.

STATE AND CONDITIONS

Variables, collision checks and boundary conditions connected player actions to a consistent game state.

DESIGN AND FUNCTION

Building custom sprites, backdrops and sound into the experience reminded me that interaction design and programming decisions work together.
